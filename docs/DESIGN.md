# Cairn 设计约束

## 功能必要性判据

一个能力是否进入本库，只看一条：上层应用若没有本库，能否自己实现。

能自己实现的一律不做。文件读写、目录遍历、参数解析、日志、配置、线程池、事件循环、UI、通用序列化，全部交给上层。这些是应用层本来就要写的东西，包进来只会让库里塞满与协议无关的代码。

不能自己实现的才做。密码学原语没人会自己写；握手与密钥调度、帧格式、分片重组、断点续传状态机、NAT 打洞状态机、蓝牙与 Wi-Fi 直连的平台差异，这些要么是协议必须逐字节一致，要么是状态机容易写错，属于上层做不对的部分。

按这条判据，断点续传必须做。它依赖协议层的分片编号与确认窗口，上层只能看到一份已完成的文件，无法在协议层续传，所以库要提供。

## 简洁的实施方式

代码规模靠分层控制，不靠砍功能。协议逻辑只有一份，放在 core 里，与平台无关。平台差异只出现在 transport 层，每个平台一个文件，只实现虚表里的几个函数。密码学按原语分文件，每个文件只做一件事。

不开源文件里堆配置项。每个公共结构体的字段都必须是协议需要或调用方必须知道的，其余一律藏在实现文件里。

## 已裁掉的依赖

不引入任何第三方库，包括测试框架。测试用自带的极简 harness，三十行以内。构建只用 CMake，不引入包管理器。
